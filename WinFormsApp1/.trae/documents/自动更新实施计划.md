# 自动更新功能实施计划（静默替换方案）

针对您希望实现**完全静默更新、直接替换文件**的需求，现调整为 **Launcher (启动器)** 方案。该方案无需用户点击任何按钮，启动时自动检测并覆盖新文件。

## 1. 方案概述

*   **核心组件**: 自研启动器 (`Launcher.exe`)。
*   **更新源**: 局域网共享文件夹。
*   **工作原理**: 
    1. 用户运行 `Launcher.exe`。
    2. 启动器自动对比**共享路径**与**本地**主程序的版本号。
    3. 如发现新版本，直接从共享路径**复制并覆盖**本地文件（无需解压）。
    4. 更新完成后，自动启动主程序 `WinFormsApp1.exe` 并退出启动器。

## 2. 实施步骤

### 2.1 新建启动器项目
在解决方案中添加一个新的控制台项目（或无界面 WinForm），命名为 `Launcher`。

### 2.2 编写核心逻辑
启动器将包含以下逻辑：
1.  **获取版本**: 读取共享路径下 `WinFormsApp1.exe` 的文件版本号。
2.  **对比版本**: 与本地版本进行比对。
3.  **执行更新**: 
    *   如果远程版本 > 本地版本：关闭主程序进程（防占用），执行 `File.Copy` 覆盖文件。
    *   **注意**: 配置文件（如 `appsettings.json`）通常不覆盖，以免丢失用户配置。
4.  **启动主程序**: 更新完成后，使用 `Process.Start` 启动主程序。

### 2.3 配置文件
在 `Launcher` 中配置共享路径地址：
```csharp
string remotePath = @"\\Server\Share\App\"; // 远程更新目录
string localPath = AppDomain.CurrentDomain.BaseDirectory; // 本地目录
```

## 3. 发布流程 (SOP)

1.  **编译主程序**: 生成新版本的 `WinFormsApp1.exe`。
2.  **发布到共享**: 将新生成的 EXE 和 DLL 文件复制到共享文件夹。
3.  **用户端**: 
    *   **首次**: 用户下载 `Launcher.exe` 放到程序目录。
    *   **之后**: 用户双击 `Launcher.exe` 即可自动完成更新并启动。

## 4. 优势与注意

*   **优势**: 
    *   **零干扰**: 用户无感知，双击即用。
    *   **简单**: 纯文件复制，不易出错。
*   **注意**: 
    *   需要将用户的桌面快捷方式指向 `Launcher.exe`。
    *   共享文件夹必须对所有用户开放**读取权限**。
